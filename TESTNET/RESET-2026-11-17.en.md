## External validators — what to do

### 1. Download and verify

Download from the release:
<https://github.com/Luggom/Luggom/releases/tag/testnet-2026-11-17>

- `luggomd` (SHA256 above);
- `genesis-draft.json` (SHA256 above).

```sh
sha256sum luggomd genesis-draft.json
luggomd version --long --output json   # version testnet-2026-11-17, commit 7fa7dfc
```

### 2. Back up

Back up at least:

```sh
cp ~/.luggom/config/priv_validator_key.json ~/priv_validator_key.json.bak
cp ~/.luggom/config/node_key.json ~/node_key.json.bak
```

Keep `priv_validator_key.json`: the gentx must use the **same consensus key** you
will run with. Do not regenerate it.

### 3. Put the draft genesis in place

```sh
cp ~/.luggom/config/genesis.json ~/.luggom/config/genesis.luggom-test.json.bak
cp genesis-draft.json ~/.luggom/config/genesis.json
```

### 4. Create your gentx

Use your operator key and the consensus key in your home:

```sh
luggomd genesis gentx <your-key> 200000000000000000000uluggom \
  --chain-id luggom-test01 \
  --home ~/.luggom \
  --keyring-backend <test|file|os> \
  --commission-rate 0.10 --commission-max-rate 0.20 --commission-max-change-rate 0.01
```

The account is already funded in the draft genesis; you do not send funds.

Verify that the gentx pubkey matches the key you will run:

```sh
luggomd comet show-validator --home ~/.luggom
```

### 5. Send the gentx

Send `~/.luggom/config/gentx/gentx-*.json` to the coordinator (Telegram group or
the address published in the release) by **2026-11-16 02:00 UTC**.

Do **not** run `collect-gentxs`; the coordinator collects all 16 gentxs and
publishes the final genesis.

### 6. Wait for the final genesis

The final `genesis.json` (with 16 gentxs) is published by **2026-11-16 12:00 UTC**
in the same release. Its SHA256 will be posted there and in the Telegram group.

### 7. Reset and start

At **2026-11-17 02:00 UTC**:

```sh
# stop the old node
sudo systemctl stop <your-luggom-unit>

# replace the draft with the final genesis
cp genesis.json ~/.luggom/config/genesis.json

# wipe old state (keeps priv_validator_key.json and node_key.json)
luggomd comet unsafe-reset-all --home ~/.luggom

# set the chain-id used by the CLI
# (the chain-id itself comes from the genesis; config.toml has no chain-id field)
sed -i 's/^chain-id = .*/chain-id = "luggom-test01"/' ~/.luggom/config/client.toml

# start with the new binary
luggomd start --home ~/.luggom
```

Configuration notes:

- `persistent_peers` can include the public seed:
  `1530baa7b3a07e0cab8dc81c9c08fccc51a47471@62.146.183.122:26656`
- If you connect by IP, set `addr_book_strict = false` in `config.toml`.
- **No state-sync at height 0.** Genesis validators start from the genesis. The old
  `trust_height`/`trust_hash` values are obsolete. State-sync only becomes useful
  for late joiners after the new chain produces snapshots.

### 8. Verify

```sh
curl -s http://127.0.0.1:26657/status   # catching_up: false, height rising
luggomd query staking validators --node tcp://127.0.0.1:26657
```

You should see **16 validators**, all `BOND_STATUS_BONDED`, and your node signing
blocks. Post your `luggom1…` account address, moniker and `catching_up: false` in
the group.

## Old chain and quorum

- The old `luggom-test` chain is abandoned. Stop your old node at the reset time;
  do not restart the old binary and do not keep producing the old chain.
- The new chain needs **11 of 16** validators online. If more than 5 do not
  update, the new chain will not start.
- Testnet LUG has no monetary value; the chain can be reset.

## Security

- Never share `priv_validator_key.json`, `node_key.json` or keyring files.
- Verify the SHA256 of the binary and the final genesis before starting.
- The notary and API are operated by the team; validators do not run them.
