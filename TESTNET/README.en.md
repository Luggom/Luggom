## Prerequisites

- Go 1.23.8 (or use `luggomd` from the testnet release).
- Rust (for the notary).
- Binaries in `build/`: `luggomd`, `luggom-api`, `luggom-extract`.

Build (only if you are not using the release binary):

```sh
go build -ldflags="-checklinkname=0" -o build/luggomd       ./cmd/luggomd
go build -ldflags="-checklinkname=0" -o build/luggom-api     ./cmd/luggom-api
go build -ldflags="-checklinkname=0" -o build/luggom-extract ./cmd/luggom-extract
```

## 1. Run a node / validator

### 1.1 Genesis (coordinator)

The coordinator generates the genesis and fixes the parameters (max_validators=180,
70% uptime slashing, minimum gas 1uluggom, `founder_address` and `api_verifier_address`).

```sh
# The notary key must be set BEFORE genesis (it writes api_verifier_address).
export LUGGOM_NOTARY_KEY_HEX="<notary-hex-key>"
./scripts/prepare-e2e-real.sh --chain-id luggom-test
```

Without `LUGGOM_NOTARY_KEY_HEX`, the chain has no verifier and **refuses mining**
(fail-closed) — it is only useful for inspection. To mine, set the key and export
`LUGGOM_NOTARY_URL`.

### 1.2 Validators (testnet mode)

On the testnet, **each validator creates its own account** and sends the gentx.
The coordinator merges the addresses and collects the gentxs.

```sh
# validators.txt — one address per line (optional: "luggom1… 200" for bond)
./scripts/bootstrap-validators.sh external validators.txt --gentx-dir ./gentxs
```

Each validator, on their side, produces the gentx:

```sh
luggomd genesis gentx <key> 200000000000000000000uluggom --chain-id luggom-test --home $HOME/.luggom
```

> ⚠️ The `local N` mode is **disposable** (generates keys and prints mnemonics) —
> never use it on the testnet. The testnet always uses `external`.

### 1.3 Bring up the nodes

```sh
./scripts/run-local-testnet.sh start     # starts everything in background
./scripts/run-local-testnet.sh status    # checks the height of each node
./scripts/run-local-testnet.sh stop
```

Ports (per node, incremented by 10):

| Service | Base port |
|---|---|
| p2p | `26656` |
| rpc | `26657` |
| LCD (REST) | `1317` |
| gRPC | `9090` |

> ⚠️ **Mandatory RESET before the testnet**: the current local chain has the pre-A-8
> state (module accounts as `BaseAccount`) — mining with the new binary would panic.
> `prepare-e2e-real.sh` already recreates the genesis from scratch.

## 2. Be a notary

The notary is the TLSNotary service that terminates the TLS connection outside the
browser, extracts the receipt and **signs** the attestation (ECDSA secp256k1).
The chain only mints with a valid signature.

### 2.1 Build

```sh
cd tlsn-verifier/servers
OPENSSL_DIR=/usr OPENSSL_LIB_DIR=/usr/lib/x86_64-linux-gnu OPENSSL_INCLUDE_DIR=/usr/include \
  cargo build --release -p tlsn-verifier-server
# → tlsn-verifier/servers/target/release/tlsn-verifier-server
```

### 2.2 Notary key

```sh
# derive the address from the key (this address goes to genesis as api_verifier_address):
./build/luggom-extract --print-address "$LUGGOM_NOTARY_KEY_HEX"
```

The same `LUGGOM_NOTARY_KEY_HEX` must be set **before** `prepare-e2e-real.sh` (§1.1),
so the genesis writes the correct address.

### 2.3 Bring it up

```sh
cd tlsn-verifier/servers/verifier
LUGGOM_NOTARY_KEY_HEX="<hex-key>" \
LUGGOM_EXTRACTOR_BIN="$PWD/../../../build/luggom-extract" \
  ../target/release/tlsn-verifier-server
```

Listens on `0.0.0.0:7047` (`/health`, `/info`, `/session`, `/verifier`, `/proxy`,
`/attestation`). Without `LUGGOM_NOTARY_KEY_HEX` the notary **does not sign** and
the API rejects mining.

### 2.4 Connect the API

```sh
export LUGGOM_NOTARY_URL=http://127.0.0.1:7047
export LUGGOM_KEYRING=GGOM
./scripts/run-api.sh    # API on :8082
```

> Notary architecture: **1 notary at launch → 3 (2 of 3) → 5 (3 of 5)**, planned for
> after mainnet. On the testnet there is a single notary.

## 3. Mine via the desktop wallet

The miner is a desktop application (Tauri); the wallet lives in your pocket.

- Linux installers: `.deb` and `.AppImage` (generated by `cargo build -p luggom-desktop` / `tauri build`).
- Tabs **Wallet · Mine · Network**.
- The **Network** tab points to the node LCD (`http://127.0.0.1:1317`).
- The **Mine** tab points to the API (`http://127.0.0.1:8082`) and the notary (`http://127.0.0.1:7047`).
- The private key **never** leaves the machine; mining happens on the desktop.

### New wallet activation (the dust)

A brand-new wallet does not exist on-chain and cannot pay a fee. The API sends an
**activation dust** **once** per address, after validating the TLSNotary proof:

- Dust = `1e7 uluggom` = **10× the mining fee** (`1e6 uluggom`).
- The account is funded for **10 attempts** (each attempt, even a failed one,
  spends the fee).
- **If it mines successfully on the 1st try**, it receives the mined LUG and the
  dust becomes irrelevant — nothing else is needed.
- **If it fails 10 times** without ever mining, the balance is drained and the
  wallet is stuck (the API does not re-send the dust). Unstick = send LUG manually
  to that address.

> ⚠️ **To review on testnet** (finding from Passo E): the dust is one-shot per
> address and finite (10 fees). The right policy — re-send after X failures or
> leave it stuck — is an open decision.

The wallet logo uses the same "L" as the site (see `../site/assets/img/mark*.png` and
`wordmark.svg`).
